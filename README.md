# Практическая работа №5. Оперативная память: куда попадают данные программы

## Эксперимент 1. Накапливаем данные по шагам
Предположение:

(1 массив): 30.5 MiB
(2 массива): 61.0 MiB
(3 массива): 91.5 MiB
(4 массива): 122.0 MiB

Нет, память процесса всегда будет больше. Чистый объём данных - это только сами элементы.

Исходное потребление памяти: 2 808 Мб

| Шаг | Сохранено массивов | Расчётный объём элементов, MiB | Рабочий набор, MiB | Изменение от начала, MiB |
| --- | -----------------: | -----------------------------: |-----------------: | -----------------------: |
| 0 | 0 | 0 | 14,74 MiB | 0 |
| 1 | 1 | 7,63 MiB | 24,69 MiB| 9,95 MiB |
| 2 | 2 | 15,26 MiB | 32,65 MiB | 17,91 MiB |
| 3 | 3 | 22,89 MiB | 40,66 MiB | 25,92 MiB |
| 4 | 4 | 30,52 MiB | 48,34 MiB | 33,60 MiB |

Исходное потребление памяти: 2 808 К
После: 34 208 К

Что наблюдали и как это объясняем: 

* Он рос строго линейно и равномерно. На каждом шаге прибавлялось одинаковое число MiB.
* Примерно одинаково, но с небольшими отклонениями.
* На шаге 0 память уходит просто на запуск платформы .NET. На шаге 4 память процесса - это вся программа целиком, а расчётный объём - это только чистые ячейки внутри массивов.
* Память конкретно нашей программы. Общая память компьютера не подходит, так как она постоянно скачет из-за Windows, браузера и других фоновых задач.
